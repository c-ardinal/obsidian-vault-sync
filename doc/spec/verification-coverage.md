# 検証範囲（アドオン用 Vault 変換と複数端末）

アドオン用 Vault 変換（以下「変換」）に関する検証の保証範囲と非保証範囲を記載する。記載のない組合せは未検証として扱う。

## 1. 検証手段

| 手段 | 対象 | 実コード | 端末数 |
| --- | --- | --- | --- |
| 2〜4 端末シミュレーション（`tests/sim/addon-conversion.test.ts`、63 件） | SyncManager、MigrationService、GoogleDriveAdapter | 使用（クラウドと暗号処理は擬似実装） | 2〜4 |
| 変換中の他端末編集（`tests/tests/code-scenario/migration-concurrent-edits.test.ts`、26 件） | MigrationService | 使用（他端末はクラウドへの直接書込で代用） | 1 + 擬似 1 |
| 形式模型（`formal/tla/Migration.tla`） | 変換手順と他端末の同期の全交錯 | 不使用（模型） | 構成は `formal/README.md` を参照 |
| 乱数シミュレーション（`tests/sim/multi-device.sim.test.ts` 他） | 通常同期（変換なし） | 使用 | 2〜3 |

## 2. 保証範囲（上記手段で検証済み）

### 2.1 変換への追従

| 項目 | 手段 |
| --- | --- |
| 稼働中の他端末が、変換後の最初の同期で変換を検出して停止（手動同期、無変更のタイマー同期） | シミュレーション、形式模型 |
| 検出時点の通知と導入画面・解除画面の表示要求（アドオン導入済み、未導入） | シミュレーション |
| 解除前の端末は変換後 Vault へ一切送信しない | シミュレーション、形式模型（`MigrationLocked`） |
| 変換後 Vault 内の全ファイルが暗号化済み（平文混入なし、「(2)」改名なし） | シミュレーション、形式模型 |
| 旧フォルダの状態 3 種（移行ロックあり、ロックなし、削除済み）での追従 | シミュレーション |
| 追従前の編集の保持（未編集は他端末の内容を採用、双方編集は両方を保持） | シミュレーション、形式模型 |
| 変換後 Vault で削除済みのノートは追従時に復活しない。追従前に編集済みの場合は編集を優先 | シミュレーション、形式模型 |
| 追従前に新規作成したノートは削除扱いにせず送信 | シミュレーション、形式模型 |
| 追従前に改名したノートは、変換後 Vault でも改名として反映（複製なし）。改名と同時の編集、変換後 Vault 側の編集も保持 | シミュレーション（3 件） |
| 4 端末混在（変換端末、稼働中・導入済み、稼働中・未導入、停止中でオフライン編集あり）での収束。変換後のパスワード変更、再ロック、改名、削除を含む | シミュレーション（2 件） |
| 他端末不在時の旧フォルダ即時削除、存在時の保持と通知 | 変換中の他端末編集テスト |

### 2.2 旧フォルダへの遅延送信（移行ロック作成前に開始した同期）

| 項目 | 手段 |
| --- | --- |
| 変換中・交換直前に他端末が旧フォルダへ送信した編集と削除の保持 | 形式模型、変換中の他端末編集テスト |
| 遅延送信ノートを変換後 Vault で削除した場合、旧フォルダの後処理でも送信端末の追従でも復活しない（削除記録との照合） | シミュレーション（5 件）、形式模型（`MigrationLateDelete` が照合なしの反例を提示） |
| 遅延送信の編集は送信端末に残存し、後処理を待機せず他端末へ到達。変換後 Vault 側の編集と競合した場合は両方を保持 | シミュレーション（3 件）、形式模型 |
| 遅延の削除・改名は、送信端末の追従時または後処理で反映。変換後 Vault で編集済みのノートは削除しない | シミュレーション（7 件） |
| 送信端末が追従直後・再送信前に終了し、その間に後処理で取込済みのノートが他端末で削除された場合も、再起動後に復活しない | シミュレーション（3 件）、形式模型（3 台構成が反例を提示して検出） |

### 2.3 変換の排他と中断

| 項目 | 手段 |
| --- | --- |
| 2 端末による変換の同時開始: 相手のロックを確認可能な場合は後発が開始を中止。確認不可能（一覧の遅延）な場合も、ロックの時刻順で後発が交換前に中止し、一時フォルダとロックを撤去して通常端末として追従 | シミュレーション（4 件） |
| 変換端末の強制終了（送信中、交換直前、2 回の改名の中間、交換直後）と他端末の同期の組合せ。交換前の終了は次回起動時に変換を破棄、改名の中間の終了は次回起動時に交換を完了 | シミュレーション（7 件） |
| 改名の中間（Vault 名のフォルダが不在）に他端末（稼働中、再起動、新規）が同期しても、空の Vault フォルダを作成しない | シミュレーション（4 件）、単体テスト |
| 変換端末が同期対象外に設定したファイルも、変換後 Vault へ変換（端末へは保存しない）。遅延送信分は後処理で取込 | シミュレーション（3 件） |

### 2.4 Vault フォルダの手動操作

| 項目 | 手段 |
| --- | --- |
| クラウド上での Vault フォルダの手動改名・削除後、端末が Vault 名のフォルダを再構築して収束（非変換・変換済み、他端末の稼働・再起動の計 8 件） | シミュレーション |
| 変換済み Vault の再構築時、鍵ファイル（vault-lock）を端末保持の複製から復元 | シミュレーション（4 件）、単体テスト（5 件） |

## 3. 非保証範囲

### 3.1 実機確認でのみ検証可能な範囲

| 項目 | 状態 |
| --- | --- |
| 実 Google Drive での動作（変更フィードの遅延・順序、検索と一覧の結果整合性、ID 指定操作の権限、容量・レート制限） | 未検証。擬似サーバーは即時整合で、実サービスとの差異は検出不可能 |
| 実アドオン（実暗号処理、実ダイアログ）と実 Obsidian 上での変換、追従、解除 | 未検証。CI の実 Obsidian 検査は導入・設定画面のみ対象 |
| モバイル（Android、iOS）固有の動作（バックグラウンド停止、ファイル名制約）と変換の組合せ | 未検証 |
| 保存済みパスワードによる自動解除の失敗経路（他端末でのパスワード変更後の再起動） | 未検証（`main.ts` の処理で、テスト対象外） |

### 3.2 設計上の制約（コードでの解消が不可能、または対象外）

| 項目 | 内容 |
| --- | --- |
| 2 端末による完全同時の交換 | Google Drive は比較交換を提供しない。ロック一覧の反映遅延が、交換直前の最終確認まで継続した場合のみ、2 端末が共に交換へ到達する。確認は開始時、後処理開始時、交換直前の 3 回 |
| 改名の中間で終了した変換端末が 24 時間以上復帰しない場合 | 他端末は 24 時間（移行ロックの有効期間）待機し、その後は端末保持の内容で非変換の Vault フォルダを再構築する |
| 鍵ファイルの複製を保持しない端末のみが残存する場合の手動削除 | 複製は解除時と鍵ファイル書込時に保存する。0.19.3 への更新後に一度も解除していない端末は複製を保持せず、同期を停止してエラーを表示する（送信なし） |
| 同期対象外ファイルの遅延削除 | 変換端末の後処理は反映しない。削除した端末が追従時に反映する（復帰しない場合、当該ファイルは変換後 Vault に残存） |
| 遅延のフォルダ間移動 | 送信端末の追従または後処理までの間、移動前の位置にも同一ノートが残存する（一時的な重複。消失なし） |
| 5 台以上、および 4 端末で上記以外の順序・組合せ | 固定手順のみで、乱数探索なし |
| 形式模型での改名 | 版番号による抽象化ではファイルの同一性を表現不可能なため、模型化を断念。シミュレーションで検証 |
| 0.19.2 以前の版と 0.19.3 の混在（旧版端末は追従処理なし） | 対象外。全端末の更新が前提 |
| 変換後 Vault の `conversion-base.json` が欠落・破損した場合 | 削除判定を行わず、ノートを保持する方向（復活）へ縮退。破損時の動作は単体テストなし |

## 4. API 呼出回数への影響

通常の同期周期（変換なし、Vault フォルダの交換なし）での呼出回数は不変。追加は下記の場合に限定する。

| 場合 | 追加呼出 |
| --- | --- |
| 変換の開始・後処理開始・交換直前 | ロック一覧の取得（各 1 回とロック件数分の取得） |
| 追従時、変換が読取した版と自端末の版が相違するノート（交換後 1 時間以内） | ノート 1 件につき ID 指定の照会 1 回 |
| Vault 名のフォルダが不在の場合 | 同階層フォルダの一覧 1 回 |
| フォルダ交換の検出時（変換済み Vault） | 鍵ファイルの存在確認 1 回 |
| 遅延送信した版と同一内容のノートに、他端末の削除が到達した場合 | 共有インデックスの取得 1 回 |
| 旧フォルダの後処理 | 共有インデックスの取得 1 回、同期対象外ファイルの取得と送信 |
