Privacy Policy

This privacy policy describes how Vault-Sync ("the Plugin"), an Obsidian plugin developed by c-ardinal, handles your data.

Data We Access

Vault-Sync accesses your cloud storage account solely to synchronize your Obsidian vault files. The Plugin requests only the minimum permissions required for synchronization and cannot access files or folders that were not created by the Plugin itself. It also reads how much of your cloud storage is used (totals only), so that it can warn you before the account fills up.

Data We Collect

The Plugin does not collect, transmit, or store any personal data on external servers. All sync operations occur directly between your local device and your cloud storage account.

  • No analytics or tracking
  • No user data is sent to the developer
  • No cookies or local identifiers for tracking purposes

Authentication Proxy

By default, the Plugin uses an authentication proxy hosted on Cloudflare Pages to facilitate the OAuth login flow. This proxy handles the following data transiently (in-memory only, never persisted):

  • OAuth authorization codes (exchanged for tokens and immediately discarded)
  • Access tokens and refresh tokens (forwarded to the Plugin and immediately discarded)

No vault data, file contents, or file metadata passes through this proxy. The proxy is used solely for the initial login and token refresh operations. You may opt out of using this proxy by configuring your own OAuth credentials in the Plugin settings.

Data Storage

  • Authentication credentials (tokens and other secrets) are stored via Obsidian's SecretStorage API. In environments where SecretStorage is unavailable, the Plugin automatically falls back to local file storage encrypted with a device-specific key (AES-GCM). Credentials are used only to authenticate with your cloud storage provider.
  • Vault files are synchronized between your local device and your cloud storage.
  • Sync metadata (file hashes, timestamps) is stored locally and on your cloud storage to manage synchronization state.
  • Device records: to tell your devices apart, the Plugin creates a random device ID and a device name that you can change. For each device, the name, platform, last sync time and a list of recently changed file paths are stored on your cloud storage. They are shown only to you and are not used for tracking.
  • Deleted files and past versions may be kept on your cloud storage for the period you set, so that they can be restored.
  • Logs: errors and other important events are recorded in a log on your device, and detailed logs only when you turn detailed logging on. Logs are uploaded to your own cloud storage only when you turn on log syncing. Logs can contain file names.
  • Network type and battery level are read on your device, where the device reports them, only to decide whether to hold large transfers. They are not sent to the developer or any third party.

Add-ons

Optional add-ons that are distributed separately from the Plugin and installed into it may handle vault data in additional ways. How an add-on handles data is described in its own additional terms, which you are asked to accept when you install it.

Third-Party Services

The Plugin integrates with the following services. Only the services you choose to connect are accessed.

Cloudflare Pages

The default authentication proxy runs on Cloudflare Pages. Cloudflare may process request metadata (IP addresses, request headers) in accordance with their Privacy Policy. No vault data is sent to Cloudflare.

GitHub

The Plugin opens GitHub in your browser only when you ask it to: to show an add-on's download page, or to report a problem from the diagnostics screen. A report opens the issue form filled with the diagnostic text shown on that screen (versions, settings without secrets, sync state and, unless you turn that option off, recent log lines that can contain file names). The text is sent to GitHub as part of the link when the form opens. It becomes a public issue only when you submit the form.

Google Drive

When using Google Drive as your sync provider, the Plugin uses the drive.file OAuth scope, which limits access to only files and folders created by the Plugin. The Plugin's use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements. For details, see Google's Privacy Policy.

Data Deletion

Logging out in the Plugin's settings revokes the Plugin's tokens and deletes them from your device. You can also revoke the Plugin's access to your cloud storage at any time through your cloud storage provider's account settings. Uninstalling the Plugin removes the data in the Plugin's own folder, including settings and sync metadata. Credentials held in Obsidian's SecretStorage are not removed by uninstalling, so log out before you uninstall. Files previously synced to your cloud storage, including kept deleted files and past versions, will remain there until you delete them manually.

Contact

If you have questions about this privacy policy, please open an issue on the GitHub repository.

プライバシーポリシー

本プライバシーポリシーは、c-ardinalが開発したObsidianプラグインであるVault-Sync（以下「本プラグイン」）におけるデータの処理方法を説明するものです。

アクセスするデータ

Vault-Syncは、ObsidianのVaultファイルを同期する目的でのみ、あなたのクラウドストレージにアクセスします。 本プラグインは同期に必要な最小限の権限のみを要求し、本プラグインが作成したファイルおよびフォルダ以外にはアクセスできません。
また、容量逼迫の事前警告を目的として、クラウドストレージの使用量（合計値のみ）を取得します。

収集するデータ

本プラグインは、個人データを外部サーバーに収集・送信・保存しません。 全同期操作は、あなたのローカルデバイスとクラウドストレージアカウント間で直接実行されます。

  • アナリティクスやトラッキングは実施しません
  • ユーザーデータが開発者に送信されることはありません
  • トラッキング目的のCookieやローカル識別子は使用しません

認証プロキシ

デフォルトでは、本プラグインはCloudflare Pages上にホストされた認証プロキシを使用してOAuthログインフローを仲介します。このプロキシは以下のデータを一時的に（メモリ上のみで、永続化しません）処理します：

  • OAuth認可コード（トークンへの交換後、即座に破棄）
  • アクセストークンおよびリフレッシュトークン（プラグインへの転送後、即座に破棄）

Vaultデータ、ファイルの内容、ファイルのメタデータがこのプロキシを経由することはありません。プロキシは初回ログインおよびトークンリフレッシュ操作にのみ使用されます。プラグイン設定で独自のOAuth認証情報を設定すれば、このプロキシの使用を回避可能です。

データの保存

  • 認証情報（トークンなどの秘密情報）はObsidianのSecretStorage APIを介して保管します。SecretStorageが利用不可能な環境では、デバイス固有の鍵（AES-GCM）で暗号化したローカルファイルに自動的にフォールバックします。認証情報はクラウドストレージプロバイダとの認証にのみ使用します。
  • Vaultファイルはローカルデバイスとクラウドストレージ間で同期します。
  • 同期メタデータ（ファイルハッシュ、タイムスタンプ）は、同期状態を管理するためにクラウドストレージ上およびローカルに保存します。
  • 端末記録：端末の識別を目的として、ランダムな端末IDと、変更可能な端末名を生成します。端末単位の名称、プラットフォーム、最終同期日時、直近の変更ファイルパス一覧を、クラウドストレージ上に保存します。これらはユーザー本人にのみ表示され、トラッキングには使用しません。
  • 削除ファイルと過去のバージョンは、復元を可能にするため、設定した期間クラウドストレージ上に保管する可能性があります。
  • ログ：エラー等の重要イベントはデバイス上のログに記録し、詳細ログは詳細ログ出力を有効化した際のみ記録します。ログの同期を有効化した際のみ、ログをユーザー自身のクラウドストレージへアップロードします。ログはファイル名を包含する可能性があります。
  • ネットワーク種別と電池残量は、デバイスが提供する際のみ、大容量ファイル転送の延期判定を目的としてデバイス上で参照します。開発者および第三者へ送信することはありません。

アドオン

本プラグインとは別途配布され、本プラグインに導入する任意のアドオンは、Vaultデータを追加の方法で処理する可能性があります。その処理方法は各アドオンの追加条件に記載され、導入時に同意を要求します。

第三者サービス

本プラグインは以下のサービスと連携します。
連携先として選択したサービスにのみアクセスします。

Cloudflare Pages

デフォルトの認証プロキシはCloudflare Pages上で動作しています。Cloudflareはリクエストメタデータ（IPアドレス、リクエストヘッダ）を同社のプライバシーポリシーに準拠して処理する可能性があります。VaultデータがCloudflareに送信されることはありません。

GitHub

本プラグインは、ユーザーが操作した際のみ、ブラウザでGitHubを表示します。対象は、アドオンのダウンロードページの表示と、診断情報画面からの不具合報告です。
不具合報告では、同画面に表示中の診断情報（バージョン、秘密情報を除外した設定、同期状態、および該当オプションを無効化しない限り、ファイル名を包含する可能性がある直近のログ）を記入済の状態で、Issue投稿画面を表示します。
診断情報はリンクの一部として、投稿画面の表示時点でGitHubに送信されます。Issueとして一般公開されるのは、ユーザーが投稿した時点です。

Google Drive

Google Driveを同期先として使用する際、本プラグインはdrive.fileOAuthスコープを使用し、本プラグインが作成したファイルおよびフォルダにのみアクセスが制限されます。
本プラグインによるGoogle APIから受信した情報の使用および転送は、制限付き使用の要件を含むGoogle APIサービスのユーザーデータポリシーに準拠しています。詳細はGoogleのプライバシーポリシーをご参照ください。

データの削除

本プラグインの設定画面でログアウトすると、本プラグインのトークンを失効させ、デバイスから削除します。
クラウドストレージプロバイダのアカウント設定から、随時本プラグインのアクセス権を無効化することも可能です。
本プラグインをアンインストールすると、設定や同期メタデータを包含する、本プラグインのフォルダ内のデータが削除されます。
ObsidianのSecretStorageに保管された認証情報は、アンインストールでは削除されないため、アンインストール前にログアウトしてください。
過去にクラウドストレージへ同期されたファイル（保管中の削除ファイルと過去のバージョンを包含）は、手動で削除するまで残存します。

連絡先

本プライバシーポリシーに関するご質問は、GitHubリポジトリでIssueを作成してください。
